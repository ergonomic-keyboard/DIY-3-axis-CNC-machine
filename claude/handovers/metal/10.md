## 3. Gotchas / decisions this session
- **The move is a REFLECTION, not a rigid translation.** Going "to the other side of the beams" flips the
  plate↔block order in X (blocks were on p1of2's +X/rear face facing the beam; now the beam-facing blocks
  are on p1of2's −X face). So I set positions explicitly from the chain constants rather than translating.
- **Kinematic groups flipped to match physics:** Rail_Z `z_slide→gantry` (fixed to p1of2); the Front
  blocks `gantry→gantry+z_slide` (they're p2of2's carriages now). Static assembly is what the user views;
  the animation is now *more* correct (blocks travel along fixed rails).
- **180° Z flip moves the STEP's off-centre router bore** from world Y433 to Y417 → `_RC_BORE_Y0` had to
  follow, or the fill/recut would leave a double bore. (Raw clamp STEP is centred at local origin, so the
  Placement rotation = rotation about the clamp centre; bbox X-span stays symmetric ±55.)
- **Rail bolts pass cleanly through the beam `_grail` holes** (∩ beam = 0) — the beam is hollow + drilled,
  so a rail screw reads as passing through the mounting hole (same intent as before; ∩ rail ≠ 0 = threads
  into the rail, which carries no clearance hole in the model).
