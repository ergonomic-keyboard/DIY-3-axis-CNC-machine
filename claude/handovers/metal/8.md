## 1. What was implemented this session

### Viewer R.0/R.1/R.2 — `assembly/view_assembly.sh` (DONE + verified)
- The final `exec freecad "$OUT"` now also passes a generated `_view_setup.py` startup macro.
  FreeCAD executes a `.py` given on its CLI once the GUI + document are up (verified with a
  marker test). The macro defers on a `QtCore.QTimer.singleShot` **retry loop** (250 ms, ≤60
  tries) until `FreeCADGui.ActiveDocument.ActiveView` exists — the script can fire before the
  doc finishes loading.
- **R.0** (object centred where the red dot is): `RotationMode=0` (rotate about window centre)
  + `ViewFit`. **R.1** (stretched to fill the window): `ViewFit`. **R.2** (touchscreen nav):
  see below.
- **R.2 caveat — there is NO nav style named "Touchscreen" in FreeCAD 1.1.1.**
  `setNavigationType` *silently ignores* unknown names (I checked: it kept CAD). Available
  styles: CAD/Inventor/Blender/Touchpad/Gesture/MayaGesture/OpenCascade/Revit/TinkerCAD. I mapped
  "touchscreen" → **`Gui::GestureNavigationStyle`** (FreeCAD's touch style: pinch-zoom /
  two-finger orbit). Settings persist to the repo `.freecad/user.cfg` (the `~/.local/bin/freecad`
  wrapper passes `--user-cfg`). **Confirm this mapping with the user** — I offered the choice and
  they declined to pick, so Gesture is my call.

## 2. Gotchas learned this session
- **FreeCAD `.py` on the CLI runs after GUI+doc load** — but the doc may not be loaded yet when it
  fires, so defer view work on a QTimer that polls `ActiveView`.
- **`setNavigationType` fails silently** for unknown style names (returns without changing). Always
  read back `getNavigationType()` to confirm. No "Touchscreen" style exists in 1.1.1.
- Everything in §2 of handover 7 still applies (placement-baking vs translate, removeSplitter,
  GUI-visibility race, classifier tokens, duplicate-solid dedupe, coord frame).
