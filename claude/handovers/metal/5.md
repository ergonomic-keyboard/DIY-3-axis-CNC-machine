  Launch GUI via the `freecad` wrapper (`~/.local/bin/freecad`). See memory

  project nix-shell, which **is not available on this machine** → those scripts

## B. YAML geometry authoring  (metal_plates part pipeline)

Goal: edit part geometry as commented/grouped/parametric YAML instead of raw JSON
or bare Python constants. **Reality of the pipeline** (discovered this session):
only **M20a** is actually built by `build_model.py`; the other parts are built by
their own Python scripts or by manual FreeCAD files.

| Part | How it's built | YAML authoring | Status |
|---|---|---|---|
| **M20a** left plate | `build_model.py` (outline + holes) | `holes.yaml`, `outline.yaml` | ✅ done, round-trips **exact** |
| M20b back clip | `back_clip.py` | `back_clip.params.yaml` | ✅ wired |
| M20cd front clips | `lower/upper_front_clip.py` | `*.params.yaml` (×2) | ✅ wired |
| M24a/M24b router clamps | `router_clamp.py` (identical copies) | `router_clamp.params.yaml` (×2) | ✅ wired |
| MX1 belt clamp | `engine_sideways_belt_clamp.py` | `*.params.yaml` | ✅ wired |
| M40a stepper holder | `engine_holder_top_plate.py` | `*.params.yaml` | ✅ wired |
| **M36a, M36b** plates | manual `manual_design/*.FCStd` | — none — | ⚠️ edit in FreeCAD, not YAML |

**Two mechanisms:**
1. **M20a (data-driven):** author `holes.yaml` (grouped holes: shared radius,
   `rect4` bolt patterns numbered clockwise-from-top-left with `dx`/`dy`, a thread
   table, datum-relative `z_from_bottom`) and `outline.yaml` (vertices + per-edge
   `constraint`/`group` + comments). Compile:
   ```
   ~/.local/opt/FreeCAD-1.1.1/usr/bin/python hardware_mods/metal_plates/expand_holes.py   --example <PART>
   ~/.local/opt/FreeCAD-1.1.1/usr/bin/python hardware_mods/metal_plates/expand_outline.py --example <PART>
   ```
   → writes `holes.json` / `outline.json`, which `build_model.py` now **prefers**
   (falls back to `holes_from_stl.json` / `*_polygon.json`). Both expanders print a
   self-check diff vs the legacy inputs; M20a currently matches **exactly**.
2. **Script parts:** each script got a `<script>.params.yaml` (constants extracted
   *with comments*; derived values snapshotted) and a guarded override block
   (`_apply_yaml_param_overrides()`). Shipped values equal the defaults ⇒ no
   geometry change until edited. Missing file / PyYAML is caught (never breaks the
   build). Lowercase/unknown keys ignored.

**README** `hardware_mods/metal_plates/README.md` has an "Authoring geometry in YAML"
section documenting all of this.

**Verified vs not:**
- ✅ M20a `holes.yaml`/`outline.yaml` round-trip bit-exact (holes match the STL net
  set; outline vertex Δ=0.00 mm, constraints/groups equal).
- ✅ Override logic tested in isolation (no-file, defaults, edit, junk-keys).
- ❌ **Not run through build123d** (no nix) — STEPs not regenerated. Do one
  `build_model.py`/script run per part in the nix-shell to confirm before relying on it.

**Notes / gotchas:**
- `build_model.py` extrudes 2-D circles, so concentric hole records collapse to the
  largest radius: M20a's 28 extracted records = **15 real holes** (that's what
  `holes.yaml` encodes).
- M20a `mgn12h_block_B` has one asymmetric hole (Ø3.5 vs Ø8 siblings) — flagged in
  the YAML; confirm against the real part.
- `holes.yaml` now survives `rectify.py` (which used to overwrite `holes_from_stl.json`).
